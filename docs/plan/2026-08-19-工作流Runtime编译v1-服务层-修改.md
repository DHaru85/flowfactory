# 2026-08-19 工作流 Runtime 编译 v1 - 服务层 - 修改

## 用户需求理解

Studio 方案第 9 节声明配置态与运行态刻意分裂：`FlowRuntime.compile` 只认 `schema_version=0`，Studio 发布的 v1 图不可被 conversation / Celery 执行。用户要求**本轮补齐 runtime**，消化第 9 节清单。

第 10 节约束继续有效：**仅 JWT，不调用 `PermissionService`**，不按角色/资产过滤 Run 或 Flow。本轮不审 RBAC、不补 `agent_flow.owner`。

现网：`flow.py` 按 `{id,kind,prompt}` + `{source,target}` + `entry_point` / `interrupt_before` 编译；worker `ainvoke` 后凡 `__interrupt__` 一律写 HITL；无 `waiting_child`；`wf_child_run_pending` 仅设计文档，ORM 未迁；`StartRunRequest.definition` 只能塞 v0；scheduler 把 definition 当 v0 写入 thread context，v1 JSON 会校验失败。

本轮目标：双读 v0/v1；按 `NodeType` 建节点；无条件边 + `FlowBranch` 条件边；子图独立 Celery Run + `waiting_child`；HITL 由 `hitl` 节点派生；子超时/取消回传；取消父级联。v0 回归单测仍过。

### 澄清过程

沿用 Studio 方案 Q2/Q4。本轮将第 9 节从「明确不做」改为「必须做」。第 10 节不改。

下列实现口径写入方案，视为本轮默认（确认后锁定）：

1. **表达式**：`assign.expr` 与 `BranchRouter.kind=expr` 使用同一受限语法，**禁止** `eval`/`exec`。支持：三槽路径（`messages` / `variables.*` / `metadata.*`）、JSON 字面量、`==` `!=`、一元 `not`、`and`/`or`、括号。`assign` 的 expr 求值结果写入 `target`。
2. **custom**：仅内置 `handler_key=passthrough`；未知 key 编译失败。不建设规划循环 / SkillRuntime。
3. **llm_ref**：节点执行时按 `agent_llm.code` 解析 `is_active` 配置构造客户端；缺失则失败该节点（Run `failed`）。单测可注入 `FakeChatCompletionClient`。
4. **鉴权**：runtime 与 conversation/studio 均不接 `PermissionService`。任意有效 JWT 用户仍可启动已发布 Flow（及既有 v0 内联 definition）。
5. **Studio**：不改表示层；不新增 invoke API。发布后的 v1 可通过既有 `WorkflowRuntimeService.start` / conversation 入队执行。

### 2. 编译入口双读

`FlowRuntime.compile` 接受 `FlowDefinitionDocument | FlowDefinitionV1 | dict`：

- `schema_version==1` 或可被 `FlowDefinitionV1` 校验 → `_compile_v1`（忽略 `view`）。
- 否则按现网 v0 `_compile_v0`（现 `flow.py` 逻辑原样迁入，行为不变）。

scheduler / worker 存取 thread `context.definition` 改为 **原始 dict**，不再强制 `FlowDefinitionDocument.model_validate`。`StartRunRequest.definition` 改为 `dict | FlowDefinitionDocument | None`，内联 v0 与 v1 均可。

v1 入口：唯一 `start` 的后继（`START → 后继`）；`end` 节点 `add_edge(该点, END)`。`start`/`end` 本身不作为业务计算节点（可注册为空操作以便观测包装，但不改三槽）。`inject` 在 **首次 `ainvoke` 前** 由 worker 写入 `RunStatePayload`，不编进图。

v1 `interrupt_before`：**不作为作者字段**。HITL 使用节点内 `interrupt()`（与现网 `kind=interrupt` 一致，resume 仍走 `Command(resume=...)`）。不把 hitl id 再写入 `compile(interrupt_before=...)`，避免二次中断。派生关系体现在：图中每个 `type=hitl` 即一个中断点。

### 3. 按 NodeType 建节点

| type | 行为 |
| --- | --- |
| `start` / `end` | 空操作；拓扑见上 |
| `llm` | 现网 llm 节点 + `system_prompt`；`stream` 为 false 时 `complete` 一次返回（不打字机） |
| `tool` | 节点内 `ToolExecutor.execute`；`arguments_from` 按路径取参；结果写入 `output_to`（`variables.*`）；`success=false` 不抛，写入 `variables.__tool_error__.{node_id}` |
| `assign` | 求值 `assignments` 写入对应槽 |
| `hitl` | `interrupt({prompt, form_schema, node_id})`；resume 写入 `variables.hitl_resume`；`on_reject=fail` 在 worker 侧 reject 时仍 `cancelled`（现网）；`on_reject=route` 时节点返回 decision 供 `hitl_decision` 分支 |
| `subgraph` | **禁止同进程 compile 子图**。见第 4 节 |
| `custom` | `passthrough` 空操作；其它 key 编译期 `ValueError` |

观测 / 护栏包装继续：`wrap_graph_node` / `wrap_guardrail_node`。v1 入口判定改为 `start` 的直接后继。

无条件边 `add_edge`；`target` 为 `__end__` 或 `end` 节点则接到 `END`。

`FlowBranch` → `add_conditional_edges`。router：

- `state_path`：路径值转 str 作为 case key
- `expr`：布尔则 `true`/`false`，否则 `str(value)`
- `hitl_decision`：读 `variables.hitl_resume`（`approve`/`reject` 或用户提交值）
- `child_status`：读 `variables.__subgraph__.{source}.status`

`max_visits`：在 `metadata.__branch_visits__.{branch_id}` 计数，超限走 `default_target`，无 default 则 Run 失败。

编译期校验：`subgraph.flow_code` 指向已 published 的校验放在 **start Run 时**（需要 DB）；compile 纯函数不查库。互引用环：start 子 Run 前沿 published definition BFS，发现环则子节点失败回传 `failed`（不把子编进父图）。

### 4. 子图独立 Run

执行到 `subgraph` 节点：

1. `input_map` 从父三槽构造子 `RunStatePayload`（无 map 则空三槽 + 不自动拷贝父 messages）。
2. `start` 子 Run（独立 `langgraph_thread_id`，`metadata.parent_run_id` / `parent_node_id`）。
3. 写 `wf_child_run_pending`（`pending`，`timeout_at` 可选）。
4. 节点内 `interrupt({"kind": "waiting_child", "pending_id", "child_run_id", "node_id"})`。
5. 当前 Celery 任务结束；worker 识别 `kind=waiting_child`：**不写 HITL**，父 snapshot=`waiting_child`。

子 Run 终态（`completed`/`failed`/`cancelled`）后：组装 `SubgraphNodeResult`，默认写入父 `variables.__subgraph__.{node_id}`，再应用 `output_map`，`resume_child`：父 `Command(resume=result)`，pending=`resumed`。

| 事件 | 子 | 父 |
| --- | --- | --- |
| 子完成/失败 | 保持终态 | resume 父，status 对应 completed/failed |
| 超时 | 取消子 | **不取消父**；`status=timeout` resume |
| 取消子 | cancelled | **不取消父**；`status=cancelled` resume |
| 取消父 | 级联取消未完成子 | pending=`parent_cancelled`，**不再 resume** |

超时：与 `expire_hitl_pending` 同类任务 `expire_child_run_pending`（可挂同一 Beat 队列）。`SubgraphNodeResult.output` 超时/取消时 hydrate 子 checkpoint，无则空三槽。

`CeleryTaskEnvelope.resume` 扩展：HITL 与 `SubgraphNodeResult` 分流（例如 `resume_kind` + 载荷），避免硬塞进 `HitlResumeInput`。

`list_active_runs` 把 `waiting_child` 视为在途。

## 验收标准（锁定后生效）

1. v0 `test_runtime_flow` 仍通过；`FlowRuntime.compile` 对 v0 文档行为不变。
