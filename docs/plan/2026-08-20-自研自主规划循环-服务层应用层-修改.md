## 施工方案

### 1. SkillRuntime（`service/tools/skill.py`）

- 读 `agent_skill`（Profile.`skill_ids`），拼接 `name` / `description` / `prompt_template` 为技能说明。
- 展开 `tool_ids` 去重，加载 `agent_tool`，得到可供模型 function-call 的 `code` + `schema` + `name`。
- 工具执行复用 `ToolExecutor`（builtin/http/mcp）；测试可通过 `GraphExecContext.tool_execute` 注入。

### 2. PlannerRuntime（`service/runtime/planner.py`）

固定 StateGraph（三槽 state，非画布，**不改** Studio `NodeType`）：

- `planner`：系统提示 = Profile.`system_prompt` + 技能说明；调用 `ChatCompletionClient.complete_turn(..., tools=)`。
- 有 `tool_calls` → `tools` 节点执行 → 写回 messages（assistant tool_calls + tool 结果）→ 再进 `planner`。
- 无工具调用或达到 `planner_max_steps`（Settings，默认 8）→ END。
- 流式：文本走既有 `speaking`；工具开始/结束发 `tool_calling`；节点发 `step_running`。护栏仍只包节点完成后的持久化 state（`wrap_guardrail_node`）。

### 3. 模型

- `complete_turn`：有 tools 时走 OpenAI tools 非流式一次（解析 `tool_calls`）；无 tools 时回退 `complete`/`stream`。
- Fake 客户端支持预设 `turns` 序列，测试不打真实模型。
- 客户端：`resolve_llm_client(llm_id=Profile.default_llm_id)`，缺省环境变量 `llm_*`；测试 override 优先。

### 4. 入队与 Worker

- 扩展 `StartRunRequest` / `CeleryTaskEnvelope`：`kind=flow|planner`（默认 flow）、可选 `profile_id`。
- **不新增** Celery 任务名；仍 `run_langgraph_flow`。规划 Run 的 `wf_run_snapshot.flow_id` 写入 `profile_id`（该列无 Flow FK）；`thread.context_payload` 记 `kind=planner` 与 `profile_id`。
- `execute_envelope`：`kind=planner` 时 `PlannerRuntime.compile`，不走 `FlowRuntime`。
- Run 完成/失败时按 `metadata.assistant_message_id` 回写 `conv_message`（`completed` + 文本块，或 `failed`）。

### 5. 应用层

- `POST /api/v1/conversations/planner/messages`：与 workflow 一样写 user + assistant(streaming)，`WorkflowRuntimeService.start(kind=planner, profile_id=..., flow_id=profile_id)`，发 `run_submitted`，返回 `run_id`。去掉 501。
- 不调用 `PermissionService`。不做规划 Beat、前端、子 Agent。
