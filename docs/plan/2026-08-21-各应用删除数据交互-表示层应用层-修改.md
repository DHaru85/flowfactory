# 2026-08-21 各应用删除数据交互 - 表示层应用层 - 修改

## 用户需求理解

现网各应用能新建与编辑，但没有删除（或停用授权）的表示交互。会话是高并发对象，宜软删；配置类对象由管理员硬删，被引用则 409。另需管理员在权限范围内管理用户（不可删用户，可封禁/停用授权），以及空闲时段清理软删数据。

## 需求中的待澄清事项

无待澄清事项（已于 2026-08-21 答复如下）

1. 会话软删；其余管理员对象硬删，被引用 409。
2. 补齐现有表示面删除；auth 增加各级管理员管理范围内用户的界面；用户不可删，授权可封禁/停用；HITL 不允许普通用户删除，只记录通过/拒绝。
3. 会话软删时，其中消息一并软删。
4. 工作流（Studio Flow）标记软删，不物理删行。
5. 模型同时保留停用与删除。
6. 增加定时任务，在空闲时间清理已标记软删且超过保留期的数据。

## 施工方案

| 对象 | 行为 |
| --- | --- |
| 会话 | `DELETE .../conversations/{planner\|workflow}/{id}`：属主 + `can_control`；`status=deleted`；同会话消息 `status=deleted`；列表/详情 404 |
| 消息 | 不单独删除接口 |
| HITL | 不提供删除；现有批准/拒绝 |
| Flow | `DELETE /studio/flows/{id}`：`status=deleted`；列表排除；被启用 Beat 或未删会话引用则 409 |
| LLM | 保留 `POST .../deactivate`；新增 `DELETE`，被 Profile 引用 409 |
| Profile/Skill/Tool/MCP/Beat | `DELETE`；先清绑定；被引用 409 |
| 用户 | `GET/PATCH /auth/users`；超管看全部，其余 `can_control(auth)` 且同组织（有部门则同部门）；`status=active\|disabled\|banned`；不可删行、不可改自身、非超管不可改超管；停用/封禁吊销会话 |
| 清理 | Celery Beat 每天 03:17（Asia/Shanghai）物理删除超过 `soft_delete_retention_days`（默认 7）的已软删会话（含消息）与无引用的已软删 Flow |

前端：会话侧栏、Studio 列表、模型表、配置各 Tab 的确认删除；`/users` 用户状态管理。验收：相关 pytest、ruff、`npm run build`。
