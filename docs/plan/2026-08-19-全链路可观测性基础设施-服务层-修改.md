# 2026-08-19 全链路可观测性基础设施建设 - 服务层 - 修改

## 用户需求理解

在 Observability 域 ORM / 仓储已落地的前提下，建设**全链路可观测**服务层基础设施，对齐总体选型 **OpenTelemetry + LangFuse**，以及 `docs/design/data_schema_server.md` 中的 `TraceCollector`、`LangfuseReporter` 与序列化对象。

覆盖：

1. **OTel 采集**：进程内创建 trace / span，结束时 `flush` 写入 `obs_trace` / `obs_span`；`otel_otlp_endpoint` 可配，空则不导出。
2. **LLM / 工具观测**：记录 usage 到 `obs_llm_call`、工具到 `obs_tool_invocation`；Prompt 入库前脱敏，原文只存 SHA-256。
3. **LangFuse 上报**：协议 + Fake + 官方 SDK 适配；默认 `langfuse_enabled=false`。
4. **编译期节点包装**：`FlowRuntime.compile` 为 `llm` / `interrupt` / `passthrough` 包一层子 span；`execute_envelope` 一次 `ainvoke` 一条 root trace，结束（含 HITL 中断、失败）即 flush。

本轮**只做服务层**：不新增 FastAPI 路由、不写 docker-compose 引入 Jaeger/LangFuse 容器。

### 澄清过程

| 事项 | 用户确认 |
| --- | --- |
| 范围 | 只执行到服务层，先不构建应用 |
| LangFuse | **必须预留接入** |
| OTel 导出 | Postgres flush 为主；endpoint 空则不导出 |
| LLM usage | 本轮记录 usage |
| 节点级 | **编译期包装**纳入本轮；不做跨 HITL 未闭合 span、tool 自动挂、框架 Callback、Celery/SQLAlchemy/Temporal 自动 instrument |
| 脱敏 | 内置邮箱 / 手机 / 身份证 / 银行卡粗匹配 + 可配额外正则 |

### 现状（不重复建设）

- 表：`obs_trace` / `obs_span` / `obs_llm_call` / `obs_tool_invocation` / `obs_prompt_snapshot` 已存在。
- 仓储：`ObservabilityRepository` 含按 otel `trace_id` 查 trace、按 run 列 LLM 调用、批量写 snapshot。
- `trace` 对 `run_id` **无外键**（仅逻辑关联）。

## 施工方案（已锁定）

### 1. 配置

`settings/config.py`：

- `otel_service_name=flowfactory`
- `otel_enabled=true`（进程内采集；无活跃 Collector 时节点包装为空操作）
- `otel_otlp_endpoint=""`（空 = 仅本地缓冲 + Postgres flush）
- `langfuse_enabled=false`
- `langfuse_host=""`、`langfuse_public_key=""`、`langfuse_secret_key=""`
- `obs_redact_extra_patterns=""`（逗号分隔额外正则）

### 2. 序列化对象

`service/observability/schemas.py`：

- `SpanAttributesPayload`：`run_id` / `flow_id` / `node_id` / `extra`
- `LlmUsageMetrics`：`trace_id` / `model` / `prompt_tokens` / `completion_tokens` / `latency_ms` / `cost_usd`
- `ToolTraceRecord`：`trace_id` / `tool_code` / `input_summary` / `output_summary` / `latency_ms` / `success`
- `TraceContext`：`trace_id` / `span_id` / `run_id` / `conversation_id` / `user_id`
- `PromptMessage`：`role` / `content`

`ChatCompletionClient.complete` **仍返回 str**。usage 在客户端内部读取并交给 Collector；Fake 的 tokens=0。

### 3. Prompt 脱敏

`service/observability/redact.py`：`redact_text` / `hash_content`（SHA-256 hex）。不承诺绝对无 PII。

### 4. TraceCollector

| 方法 | 说明 |
| --- | --- |
| `start_trace(name, context)` | 根 span |
| `end_trace(status)` | `ok` / `error`；HITL 中断记 `ok` |
| `record_span(name, attributes)` | 子 span 上下文管理器 |
| `record_llm_call(...)` | 缓冲 + 可选 LangFuse |
| `record_tool(...)` | 缓冲 + 可选 LangFuse |
| `flush(session)` | 批量写 `obs_*`，按 `span_id` UNIQUE 跳过已存在行 |

`trace_id` / `span_id` 来自 OpenTelemetry SDK，不手写伪造。Celery prefork 后重置 ContextVar。

### 5. Langfuse Reporter

| 模块 | 职责 |
| --- | --- |
| `LangfuseReporter` 协议 | `report_generation` / `report_tool` / `shutdown` |
| `FakeLangfuseReporter` | 内存记录 |
| `NoOpLangfuseReporter` | `langfuse_enabled=false` 时工厂返回 |
| `SdkLangfuseReporter` | 官方 SDK；缺配置不在 import 期崩溃 |
| `get_langfuse_reporter()` | 可 override |

适配器不依赖 ORM。上报失败只打 loguru，不打断 run。

### 6. 运行时衔接

- `OpenAICompatClient` / `FakeChatCompletionClient`：有活跃 Collector 时记 usage 与脱敏 snapshot。
- `wrap_graph_node`：compile 时包装三类节点。
- `execute_envelope`：`ainvoke` 前后 `start_trace` / `end_trace` / `flush`。

本轮不做：跨 HITL 未闭合 span、tool 节点自动埋点、LangChain Callback、`astream_events` 全量埋点、Celery/SQLAlchemy/Temporal 自动 instrumentation。

### 7. 依赖与测试

- 依赖：`opentelemetry-api`、`opentelemetry-sdk`、`opentelemetry-exporter-otlp-proto-http`、`langfuse`。
- 单测：脱敏、Collector、Fake reporter、SDK 可构造、节点包装、OTLP 空 endpoint 无网络。
- 集成：flush 写入 `obs_*`（需 Postgres）。

## 方案待澄清事项

无待澄清事项（方案锁定）。

## 验收标准

1. ruff 无 error；新增/既有 pytest 通过。
2. `start_trace` → `record_span` / `record_llm_call` / `record_tool` → `end_trace` → `flush` 可在 `obs_*` 查到记录；prompt 仅为脱敏文本且 `content_hash` 稳定。
3. `langfuse_enabled=false` 时不上报外网；注入 Fake 时可断言 generation/tool 被调用。
4. `SdkLangfuseReporter` 可独立构造（配置齐全时），缺配置不在 import 期崩溃。
5. `otel_otlp_endpoint` 为空时无 OTLP 网络调用。
6. 一次 LLM 图 run 的 `obs_span` 含节点 id；HITL 中断当次也会 flush，不把 span 留到 resume。
