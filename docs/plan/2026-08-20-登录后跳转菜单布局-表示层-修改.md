# 2026-08-20 登录后跳转菜单布局 - 表示层 - 修改

## 用户需求理解

登录（及注册成功自动入会话）后，应进入带侧栏菜单的壳布局（`AppShell`），而不是停留在登录页。当前现象：提交登录成功后页面不进入菜单布局。

根因：`App` 在渲染时用三元表达式 `isLoggedIn() ? <AuthedApp /> : <Navigate to="/login" />` 作为 `path="/*"` 的 `element`。`App` 未订阅路由或会话状态，登录写入 `sessionStorage` 并 `navigate("/")` 后 `App` 不重渲染，路由仍使用登录前算出的 `<Navigate to="/login" />`，用户被挡回登录页。

## 需求中的待澄清事项

无待澄清事项。

## 施工方案

1. 施工范围：`src/frontend/source`（表示层 / frontend）。不改后端。
2. 在 `App.tsx` 抽出 `RequireAuth`：在**子组件渲染时**读取 `isLoggedIn()`，已登录渲染 `AuthedApp`，否则 `<Navigate to="/login" replace />`。`path="/*"` 的 `element` 固定为 `<RequireAuth />`，避免把登录判定提前冻在父组件上次渲染的 element 上。
3. 已登录访问 `/login`、`/register` 时重定向到 `/`（进入 `HomeRedirect` → 菜单布局）。
4. 登出仍清 session 并 `navigate("/login")`；因 `RequireAuth` 在匹配 `/*` 时重新判定，无需额外全局 store。
5. `npm run build` 通过。

## 方案待澄清事项

无待澄清事项（用户确认后锁定，不再修改本文）。

## 验收标准

1. 登录成功后进入 `AppShell`（侧栏菜单可见），不再停在登录页。
2. 注册成功并写入 token 后同样进入菜单布局。
3. 已登录打开 `/login` 会进入菜单布局。
4. `npm run build` 成功。
