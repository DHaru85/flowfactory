# 2026-08-20 SSE 等整段生成才出字 - 服务层表示层 - 修改

## 用户需求理解

规划会话 SSE 仍像「等大模型全部生成完才返回」。询问是否要给模型设 `streaming=True`，或流式处理有误。

结论：**不必再设 `streaming=True`。** `OpenAICompatClient.stream` 已 `stream=True`。现网 POST `/messages` 已立即 200，LLM `stream` 也已开始；卡的是 **token 送到浏览器的路径**，不是模型接口没开流。

1. **同 loop eager**：publish 只走 RabbitMQ，再由本进程 exclusive queue consume 回 `_subs`。消费者与 LLM `async for` 抢同一事件循环，帧常在生成结束后才进 SSE Queue，表现为打字机失效。
2. **Vite `/api` 代理默认缓冲**，且 fetch 未带 `Accept: text/event-stream`，开发态 SSE 会被攒到一段才刷。
3. 乐观气泡 id 是临时的，SSE `speaking.message_id` 是落库 id，对不上时增量不可见。

## 需求中的待澄清事项

无待澄清事项

## 施工方案

1. `AmqpStreamEventBus.publish`：先 `put_nowait` 本地 `_subs`，再 AMQP 扇出；消息带 `origin`，本实例 `_on_message` 丢弃自己发出的帧，避免双投。
2. Vite proxy：`/events` 禁用缓冲（`X-Accel-Buffering`、立即 `flushHeaders`、timeout 0）。
3. SSE fetch：`Accept: text/event-stream`，`cache: no-store`。POST 返回后立刻把乐观助手 id 换成真实 `assistant_message_id`。
