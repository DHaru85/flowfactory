# 2026-08-19 Flow 图定义文档结构 - 映射层 - 修改

## 用户需求理解

用户要优化 `agent_flow.definition` 中保存的 **Graph 描述**（`docs/design/data_schema_server.md` 原 `FlowDefinitionDocument` 与 888–930 行节点/边草案），使其同时满足：

1. 服务层据此构建 `GraphState`、节点/边实例，编译为可运行 `StateGraph`。
2. 表示层据此展示用户编排结果（画布）。

澄清过程：

1. 原稿用 `pre_obj`/`next_obj`/`level`、`node_data: str`、把 loop 当边类型，与现网 `FlowRuntime.compile`（`{id,kind,prompt}` + `{source,target}`，三槽 state）不对齐。已给出优化原则：逻辑与 `view` 分离、拓扑只存在边、类型用 discriminator、条件路由用分支表。
2. **Q1 子图执行**：子图使用**独立 State**，提交 **Celery 新 Run**；父 worker 保留 checkpoint 后释放，进入等待。
3. **子超时/取消**：取消子 Run，把超时/取消作为**子的输出**还给父；父继续 resume，不因子超时/取消而自动取消。
4. **Q2 顶层通道**：先**锁定三个槽位**（`messages` / `variables` / `metadata`），便于 reducer 管理；不开放自定义顶层通道。

本轮只改设计文档（及必要的关联说明），**不改** `service/runtime` 编译器与 ORM。现网 `{id, kind, prompt}` 文档视为 `schema_version=0`，新结构为 `schema_version=1`，编译器双读留给后续 runtime 轮次。

### 派生默认（与 Q1 配套，避免孤儿子 Run）

取消**父** Run 时：级联取消未完成子 Run；父不再 resume（父已取消，不存在「把子输出还给父」）。若与产品意图不符请在确认前指出。

## 需求中的待澄清事项

无待澄清事项（子图调度、超时/取消回传、三槽锁定已确认）。

## 施工方案

### 1. 替换 `FlowDefinitionDocument` 与节点/边草案

删除松散 `list[dict]`、`entry_point`、`interrupt_before` 作为**作者字段**（`interrupt_before` 改为由 `hitl` 节点编译派生，写入说明即可）。删除 `FlowNodes`/`FlowEdges` 上的 `level`、`pre_obj`、`next_obj`、字符串 `node_data`/`edge_data`。删除 `EdgeType=loop` 与「默认边上做状态管道」。

根文档字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `schema_version` | int | `1` 为本文结构；`0` 为现网松散 dict |
| `state` | `GraphStateSpec` | 仅声明三槽及 reducer，不含运行值 |
| `nodes` | list[`FlowNode`] | 恰一个 `start`，至少一个 `end` |
| `edges` | list[`FlowEdge`] | 无条件边，只连节点 |
| `branches` | list[`FlowBranch`] | 条件扇出（含回边退出） |
| `view` | `FlowView` \| null | 画布；编译忽略 |

### 2. `GraphStateSpec`：锁定三槽

`channels` 固定三条，名称不可增删：

| name | reducer | 说明 |
| --- | --- | --- |
| `messages` | `append` | 对话列表 |
| `variables` | `merge` | 业务 dict；Flow 可用 `json_schema` 约束**内层键**，不是新顶层通道 |
| `metadata` | `merge` | 运行上下文 |

节点更新 state 仍返回这三 key 的子集。业务扩展只进 `variables`。`RunStatePayload` 保持三字段。`agent_checkpoint_schema.state_schema` 可由该 spec 生成（含 `variables.json_schema`）。

父子图均为三槽；差异只在 `variables` 的 schema 与 `input_map`/`output_map` 路径（`messages` / `variables.*` / `metadata.*`）。

### 3. `FlowNode` / `NodeType` / 各 `data`

`FlowNode`：`id`、`type`（discriminator）、`title`（可空，仅展示）、`data`（对象，禁止 str）。

| type | data 要点 | 编译意图（文档级，本轮不实现） |
| --- | --- | --- |
| `start` | `inject`: `{source, channel, key}[]`，`source`∈`run`/`user`/`conversation`/`beat`/`clock`；`channel` 仅三槽 | `START`→后继；inject 在入图前写入，不把会话快照/cron 写进定义 |
| `end` | `output_channels`：写入父/本 Run `output_payload` 的通道名 | →`END`；不描述进程资源回收 |
| `llm` | `llm_ref`、`system_prompt`、`stream` | 对齐现网 llm 节点 |
| `tool` | `tool_code`、`arguments_from`、`output_to`（`variables.*`） | 节点内 `ToolExecutor` |
| `assign` | `assignments`：`{target, expr}[]`，`target` 仅 `variables.*`/`metadata.*` | 替代「边上改 state」 |
| `hitl` | `prompt_template`、`form_schema`、`on_reject` | `interrupt()`；派生 `interrupt_before` |
| `subgraph` | `flow_code`+`version`、`input_map`、`output_map`、`timeout_seconds` | **新 Celery Run + 独立 checkpoint**，见第 4 节 |
| `custom` | `handler_key`、`config` | 注册表；现网 `passthrough` 映射 `handler_key=passthrough` |

禁止图 JSON 内嵌可执行代码。子图定义不展开子节点列表；画布下钻读目标 Flow 的 `definition.view`。

### 4. 边与分支

`FlowEdge`：`id`、`source`、`target`（节点 id 或 `__end__`）、`label`（可空）。无 transform。

`FlowBranch`：`id`、`source`、`router`（`state_path` / `expr` / `hitl_decision` / **`child_status`**）、`cases`、`default_target`、`max_visits`（回边防死循环）。循环 = 指向上游的边或 case，退出条件写在同一 branch。

`FlowView`：节点坐标、边锚点、分组、可选 `computed_levels`（保存前可重算，以逻辑图为准）。

### 5. 子图：独立 Run、等待、超时/取消回传

在 **Workflow Execution** 节补充（仍只写设计，不建表）：

- 父跑到 `subgraph`：按 `input_map` 从父三槽抽出子 `RunStatePayload` → `start` 子 Run → 父对该节点挂起（checkpoint 已落 PG）→ 当前 Celery 任务结束。
- 新表（逻辑名）`wf_child_run_pending`：`id`、`parent_run_id`、`child_run_id`、`node_id`、`status`、`timeout_at`、`resume_payload`。不复用 `wf_hitl_pending`。
- 父 `wf_run_snapshot.status` 增加 `waiting_child`（与 HITL 的 `interrupted` 区分）。
- 子 `langgraph_thread_id` 不得与父相同。

**子完成**：`completed` / `failed` 时组装 `SubgraphNodeResult`，`output_map` 写入父三槽后 `resume` 父。

**子超时 / 取消（已确认）**：

1. 取消子 Run（`cancelled`）。
2. 不取消父。
3. 将超时或取消作为子输出还给父，再 resume 父。

`SubgraphNodeResult`（写入父 `variables` 的约定键，例如 `variables.__subgraph__.{node_id}`，并允许 `output_map` 覆盖）：

| 字段 | 说明 |
| --- | --- |
| `status` | `completed` / `failed` / `cancelled` / `timeout` |
| `output` | 子三槽快照；超时/取消时为取消前最后 checkpoint 或空三槽，文档写明「以取消瞬间 hydrate 为准，没有则为空」 |
| `error` | `failed` 时的错误信息，其余可空 |

父图用 `FlowBranch.router=child_status` 对 `completed`/`failed`/`cancelled`/`timeout` 分流。超时由 pending 的 `timeout_at` + Beat/过期任务触发：先 `cancel` 子，再按上表 resume 父。

**取消父（派生默认）**：级联 `cancel` 所有 `waiting_child` 的未完成子；父 `cancelled`，不再 resume。

### 6. 校验规则（发布 Flow 时，文档列出）

- `schema_version=1`：唯一 `start`，≥1 个 `end`；所有边/分支端点存在；`handler_key`/`tool_code`/`flow_code` 为引用不是内嵌代码。
- `subgraph` 目标须 `published`；编译期禁止 Flow 代码级环（A 定义引用 B、B 引用 A）；运行期回边允许，靠 `max_visits`。
- 现网 version `0` 文档保留字段说明，供后续编译器双读。
