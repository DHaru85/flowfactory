# 2026-08-19 工作流编排 Studio - 应用层 - 修改

## 用户需求理解

用户要求启动 **应用层** 工作流编排 Studio 施工。对齐约定：一类交互场景一个 Application；FastAPI REST；数据走已有仓储；`agent_flow.definition` 已规范为 `FlowDefinitionDocument` `schema_version=1`（三槽、节点 discriminator、边/分支、view）。

现网：`auth` / `conversation` 已挂载；`FlowRuntime.compile` 只认 version `0`（`{id,kind,prompt}` + `{source,target}`）；`AgentFlow.profile_id` 非空。

本轮：应用层 Studio 围绕 **Workflow 图** 做创建 / 校验 / 保存 / 发布；不做表示层；不做自主规划；不改 runtime 编译器；不审角色权限。

### 澄清过程

1. **Q1 表示层**：先不做。已确认。
2. **Q2 runtime**：先不动 runtime。Studio 落库并校验 v1；`FlowRuntime.compile` 仍只认 v0。用户确认须在本方案写明「runtime 尚未完成」。见第 9 节。
3. **Q3 范围**：集中 Workflow，不建设自主规划（规划循环、SkillRuntime、Agent 自选工具、Beat、目录写接口）。图内静态 `tool` 节点仅 schema 校验。
4. **Q4 鉴权**：有效 JWT 必须有。本阶段是基础设施与原始应用，未接业务权限定义，**不审核角色是否具备权限**。须在本方案写明。见第 10 节。

## 施工方案

> 方案已锁定。

### 1. 应用 `studio`

`app_key=studio`，`src/backend/api/apps/studio/`，前缀 `/api/v1/studio`。不建设前端。

### 2. Flow 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/flows` | `offset`/`limit`/`status`/`code` 可选 |
| POST | `/flows` | 创建 `draft` version=1；`definition` 空则写入合法空图 |
| GET | `/flows/{flow_id}` | 含 `definition` |
| PATCH | `/flows/{flow_id}` | 仅 `draft` |
| POST | `/flows/{flow_id}/publish` | `draft`→`published`；同 code 其它 published → `archived` |
| POST | `/flows/{flow_id}/new-draft` | 从已发布复制 `version+1` 的 draft |

校验失败 `400 definition_invalid`。非 draft 不可 PATCH：`400 flow_not_draft`。`409 flow_code_version_conflict`。`404 flow_not_found`。无 token：`401`。

不实现：invoke、子图入队、HITL 运行、物理删除。

### 3. 图定义模型

`service/runtime/definition_v1.py`：设计文档 schema_version=1 的 Pydantic 与图论校验（不 compile LangGraph）。**不改** `schemas.py` 中 v0 `FlowDefinitionDocument` 与 `flow.py`。

### 4. 只读目录

`GET /profiles`、`GET /llms`（`is_active`）、`GET /tools`、`GET /flows/published-codes`。不下发 LLM `config`。

### 5. 仓储

`list_flows`、`list_published_flow_summaries`、`archive_published_siblings`。不改表结构。

### 6. 文档与测试

`api_reference_server.md` 增加 `studio`。单测：401、空图、非法 definition、PATCH published、publish 归档、目录。ruff 无 error。`test_runtime_flow` 回归仍过。

### 7. 明确不做

表示层；compile v1；子图 Celery / `wf_child_run_pending`；Beat；Profile/LLM/Tool 写；规划循环；限流；`PermissionService`。

### 8. 施工状态

开工后 `应用层 / api` 施工中。不改 `service/runtime/flow.py`。完成后空闲并写简报。

### 9. Runtime 尚未完成（Q2，必须保留）

本轮 **只把 v1 图定义落到配置态**（Pydantic 校验 + `agent_flow.definition` JSONB + 发布状态机）。

**尚未完成、不在本轮施工：**

- `FlowRuntime.compile` 仍只消费 `schema_version=0`（`kind`/`entry_point`/`interrupt_before`）。
- 不会把 start/end、`FlowBranch`、子图独立 Run、`waiting_child` 编进 `StateGraph`。
- Studio **publish 成功不等于可被 conversation / Celery 执行**。对 v1 图调用 `WorkflowRuntimeService.start` 的行为未定义、不应作为本轮验收。
- 子图超时/取消回传、HITL 由 hitl 节点派生 `interrupt_before`，均未实现。
- 后续 runtime 轮次需要：双读 v0/v1、按 `NodeType` 建节点、条件边、子图入队。在此之前，会话侧继续使用库中既有 v0 `definition`（或 `StartRunRequest` 内联 v0）。

配置态与运行态暂时分裂是刻意的，不是设计作废。

### 10. 鉴权：仅 JWT，不审角色（Q4，必须保留）

本轮所有 Studio 接口（除健康检查外）要求 `Authorization: Bearer <access_token>`，沿用 `get_current_user`。无效/缺失 token → 401。

**不调用** `PermissionService.check`，不读取 `sys_asset` / 角色 grants，不按组织或创建人过滤 Flow 列表。任意有效登录用户可读写 **全部** Flow。`agent_flow` 无 owner 字段，本轮不补。

原因：当前是基础设施与原始应用，尚未接入业务权限模型。编排结果仍持久化并区分 draft/published/archived，但 **不参与 ACL**。业务接入后应由 `iam` 挂 `asset_type=flow`（或组织范围）再收紧；本轮验收不以「无权 403」为准。
