## 施工方案

### A. 子图画布下钻（表示层）

1. 属性面板「下钻」：`GET /studio/flows?status=published&code=`，匹配 version（空则最大已发布），再 `GET /studio/flows/{id}`。
2. 栈 `{ flowId, code, version, document }[]`；下钻 push，面包屑 pop。栈深 > 0 时只读，保存仍提交根草稿。
3. 栈内重复 `code@version` 或总深度 ≥ 8 拒绝。目标缺失/非 v1/`403` 提示且不 push。
4. 不内嵌子节点，不改 compile。

### B. HITL 恢复（应用层 + 表示层 + worker 补事件）

1. 传输对象：`HitlPendingOut`、`HitlResumeBody`；`form_schema` 随 pending。
2. HTTP（`conversation` 可见可用；属主或超管；越权 `404 hitl_not_found`）：
   - `GET /api/v1/conversations/workflow/hitl-pendings`
   - `GET /api/v1/conversations/workflow/hitl-pendings/{hitl_id}`
   - `POST .../resume` → `WorkflowRuntimeService.resume`
3. 非 pending：`400 hitl_not_resumable`。
4. worker 写 pending 后发 SSE `run_interrupted`（保持 `run_active`）；前端拉待办并批准/拒绝。规划会话不接 HITL。
5. 待办列表页（同应用）。

### 明确不做

知识库、Docker、嵌套 compile、子图 waiting 管理台、Run 列表/取消、Temporal 替换 Passthrough。

## 方案待澄清事项

## 验收标准

1. Studio 可下钻只读已发布子图并面包屑返回；保存只提交父 `definition`。
2. 工作流会话可对 `pending` HITL 批准/拒绝。
3. 非属主不能恢复他人待办。
4. 相关 pytest 通过；`npm run build` 通过。
