# 2026-08-18 工作流运行时环境基础设施建设 - 服务层 - 修改

## 用户需求理解

在映射层 / 数据层已落地（Run/Thread/HITL/Celery 任务记录、Beat 任务配置、Redis key）的前提下，建设**工作流运行时环境**服务层基础设施，覆盖三点：

1. **多进程隔离与执行调度**：Celery prefork + 可配置 RabbitMQ broker。本轮测试与本地默认走 **eager / 内存 broker**，真实 MQ 连接串可配、稍后接入。FastAPI 不跑长 LangGraph；任务提交、重试、并发上限、崩溃隔离由 Celery worker 承担。图内 checkpoint / 中断归 Postgres checkpointer。
2. **外层编排设施**：`OuterOrchestrator` 协议 + 默认 `PassthroughOrchestrator`（直连 Celery）+ 可配置启用的 Temporal 骨架。Activity 内驱动 Celery/LangGraph，不复制图内 checkpoint。
3. **HITL 与 Beat**：人机中断待办的创建 / 恢复 / 过期；Beat 按 `agent_beat_task.cron` 触发 Run，Redis 分布式锁防重复触发。

本轮**接入真实 LangGraph + Postgres checkpointer**。不做 FastAPI 应用路由、不做 SSE、不写 docker-compose。Postgres 沿用现有实例；Redis 改为 `192.168.129.53:6479`、无密码、db `4`。

## 施工方案（已锁定）

### 1. 配置

`settings/config.py`：

- Redis 默认改为 `redis_host=192.168.129.53`、`redis_port=6479`、`redis_password=None`、`redis_db=4`
- RabbitMQ：`rabbitmq_url`（默认空或占位 URL）；`celery_eager` 默认 `true`（无 broker 时 eager）
- Celery：`celery_queue_run` / `celery_queue_beat`、`celery_worker_concurrency`、`celery_task_time_limit`、`celery_task_soft_time_limit`
- Temporal：`temporal_enabled` 默认 `false`、`temporal_host`、`temporal_namespace`、`temporal_task_queue`
- Beat：`beat_system_user_id`、`beat_tick_seconds` 默认 60
- HITL：`hitl_default_ttl_seconds`

### 2. 序列化对象（对齐 `data_schema_server.md`）

`service/runtime/schemas.py`：

- `RunStatePayload`、`ThreadContextPayload`
- `HitlResumeInput` / `HitlResumeOutput`
- `CeleryTaskEnvelope`、`BeatTaskTriggerPayload`
- `FlowDefinitionDocument`（nodes / edges / entry_point / interrupt_before）

### 3. 多进程隔离与执行调度

`service/runtime/` + `service/celery_app/`：

| 模块 | 职责 |
| --- | --- |
| `celery_app/app.py` | Celery 实例；`task_always_eager` 由配置控制；`task_acks_late`、`task_reject_on_worker_lost`；prefork |
| `celery_app/tasks.py` | `run_langgraph_flow`、`resume_langgraph_flow`、`dispatch_beat_tasks`、`expire_hitl_pending` |
| `celery_app/signals.py` | `worker_process_init` 重建 DB/Redis 客户端；task prerun/postrun 更新 `wf_celery_task_record` |
| `runtime/run.py` | `Run`：`start` / `resume` / `cancel` / `persist` |
| `runtime/thread.py` | `Thread`：`bind_worker` / `persist` |
| `runtime/scheduler.py` | 写 snapshot、投递 Celery、写 task record |
| `runtime/flow.py` | `FlowRuntime`：从 `FlowDefinitionDocument` 编译 LangGraph `StateGraph`，挂 Postgres checkpointer |
| `runtime/checkpoint.py` | `CheckpointInstance`：从 checkpointer hydrate / apply_delta |
| `runtime/worker_loop.py` | hydrate Run → `astream`/`ainvoke` → 写 snapshot / HITL / 热状态 |

队列约定：`wf.run`（执行与恢复）、`wf.beat`（Beat 扫描与 HITL 过期）。

Worker 内每个任务用 `asyncio.run` 包裹异步 Session；prefork 子进程不与父进程共享引擎。

热状态：补齐 `WorkflowCacheStore`（`wf:run:active:{run_id}`、`wf:hitl:notify:{hitl_id}`）。

### 4. LangGraph 与 Checkpointer

- 依赖：`langgraph`、`langgraph-checkpoint-postgres`
- Checkpointer 使用异步 Postgres 连接（与现有 `async_database_url` 同库）；进程启动或首次编译时 `setup()` 创建框架表
- `FlowDefinitionDocument` 编译规则：
  - 节点 `kind`：`passthrough`（透传 state）、`interrupt`（节点内 `interrupt()` 等人审）；未知 kind 视为 passthrough
  - `interrupt_before` 写入 `compile(interrupt_before=...)`
  - state 至少含 `messages` / `variables` / `metadata`（对齐 `RunStatePayload`）
- 本轮不接真实 LLM 调用；图可恢复、可中断，供 HITL/Beat 跑通

### 5. 外层编排

`service/orchestration/`：

- `OuterOrchestrator`：`start_run` / `resume_run` / `cancel_run` / `signal_hitl`
- `PassthroughOrchestrator`：默认，直连 `Run` / Celery
- `temporal/`：Workflow/Activity/Worker 骨架；Activity 只调用服务层，不写 checkpoint
- 工厂按 `temporal_enabled` 选择；默认 false 时不要求 Temporal 服务可达
- 依赖：`temporalio`（client SDK，单元测试 mock）

**硬约束**：Temporal 不写 LangGraph checkpoint；不把图节点拆成 Temporal Activity。

### 6. HITL

`service/runtime/hitl.py`：

- 图中断：写 `wf_hitl_pending`（`pending`），Run=`interrupted`
- `resume(HitlResumeInput)`：校验 → 写 `resume_payload` / `approved|rejected` → 投递 `resume_langgraph_flow`（`Command(resume=...)`）
- `reject`：Run=`cancelled`，不再入队
- `expire_hitl_pending`：过期置 `expired`，Run=`cancelled`

### 7. Beat

`service/runtime/beat.py` + 固定 tick 任务 `dispatch_beat_tasks`：

- 读 `list_enabled_beat_tasks`，`croniter` 判断窗口
- `AgentCacheStore.acquire_beat_lock` 成功才触发
- 以 `beat_system_user_id` 创建 Run 并 `start()`；未配置则打错误日志并跳过
- 更新 `last_triggered_at`
- 业务 cron 以 PG 表为准，Celery Beat 只跑固定 tick（eager 模式下由测试直接调用 tick）

本轮不新增 docker-compose。

## 验收标准

1. ruff 无 error；新增/既有 pytest 通过。
2. eager 模式下 `Run.start` 能驱动 LangGraph 最小图，snapshot 到 `completed`。
3. HITL：中断写 pending，resume 用 checkpointer 续跑，reject/expire 状态正确。
4. Beat：cron 窗口内 Redis 锁保证只触发一次。
5. 默认外层编排为 Passthrough；`temporal_enabled=true` 可选 Temporal 骨架且不强制连接服务器。
6. Redis 默认连接 `192.168.129.53:6479` db=4；prefork 子进程初始化重建 DB/Redis 客户端。
