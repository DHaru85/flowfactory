# 2026-08-19 内容护栏基础设施建设 - 服务层 - 修改

## 用户需求理解

在 Security 域 ORM / 仓储已落地、观测侧已有 Prompt 脱敏的前提下，建设**内容护栏**服务层基础设施，对齐总体选型「LangGraph 节点钩子 + 独立策略服务」，以及 `docs/design/data_schema_server.md` 中的 `GuardrailEvaluator`。

覆盖：

1. **图入口 `check_input`**：越狱 / 注入启发式检测（`rule_type=jailbreak`）。
2. **图出口 `check_output`**：PII / 敏感词（`rule_type=pii` / `keyword`）；支持流式逐块累积接口，供后续 SSE 使用。当前 worker 仍为 `ainvoke`，对本轮即对完整输出做一次检查。
3. **独立策略服务预留**：`PolicyDetector` 协议 + Fake + HTTP 适配；默认关闭，缺配置不在 import 期崩溃。
4. **编译期节点包装**：入口节点前跑 input；`llm` 节点返回后跑 output。命中 `block` 使当次 Run 失败；`mask` 改写文本后继续；`log` 只写违规仍放行。
5. **违规落库**：`sec_policy_violation`；`matched_excerpt` 为脱敏后片段。

本轮**只做服务层**：不新增 FastAPI、不做接口限流 `RateLimiter`（同域但非本次需求）、不引入分类 ONNX、不承诺绝对安全。

## 施工方案

### 1. 配置（`settings/config.py`）

- `guardrail_enabled=true`：关闭则包装为空操作，检查恒 `allow`
- `guardrail_builtin_rules=true`：库中无启用规则时仍加载内置 jailbreak/pii/keyword 最小集，便于空库可测
- `guardrail_policy_url=""`：空则不调远程
- `guardrail_policy_timeout_seconds=2.0`
- `guardrail_excerpt_max_chars=200`

### 2. 序列化对象（`service/guardrail/schemas.py`）

对齐设计文档：

- `GuardrailCheckInput`：`text` / `stage` / `context`（`run_id` / `user_id` / `conversation_id` 等）
- `GuardrailCheckOutput`：`passed` / `action`（`allow`|`block`|`mask`）/ `masked_text` / `violated_rule_codes`
- 补充 `GuardrailHit`（内部）：`rule_code` / `rule_id` / `action` / `excerpt`

`context` 类型为 `dict[str, object] | None`，不用 `Any`。

### 3. 规则引擎

`rule_type`：

| 类型 | 行为 | `config` 要点 |
| --- | --- | --- |
| `jailbreak` | 正则 / 子串列表，默认 `action=block` | `patterns: list[str]`，`action` |
| `keyword` | 大小写不敏感词表 | `words`，`action`（block/mask/log），mask 用 `replacement` |
| `pii` | 邮箱/手机/身份证/银行卡（与观测脱敏同类规则） | `action` 默认 mask；可附加 `extra_patterns` |

未知 `rule_type` 记 warning 并跳过。多规则命中时 **block > mask > log > allow**。`log` 在 Output 中仍 `passed=true` 且 `action=allow`，但写 violation。

内置默认规则（`guardrail_builtin_rules`）：少量中英越狱短语、PII mask、空 keyword 表（可被库表覆盖同 `code`）。

规则来源：`SecurityRepository.list_enabled_rules(stage)` ∪ 内置；同 `code` 以库表为准。

### 4. GuardrailEvaluator

| 方法 | 说明 |
| --- | --- |
| `check_input` / `check_output` | 同步评估 + 缓冲 violation |
| `consume_chunk(text)` | 输出流式累积（内部 buffer） |
| `finalize_output()` | 对累积文本 `check_output` |
| `flush(session)` | 批量 `record_violation`；excerpt 再走脱敏 |

构造需要预加载的 `list[GuardrailRule]`（或内置 DTO），**评估路径不访问 ORM**，以便图节点内调用。`session` 仅 `flush`。

`block` 抛 `GuardrailBlockedError`（含 `codes`），由 `execute_envelope` 落入现有 `RUN_FAILED`。

### 5. 独立策略服务预留

| 模块 | 职责 |
| --- | --- |
| `PolicyDetector` 协议 | `detect(text, stage) -> list[GuardrailHit]` |
| `FakePolicyDetector` | 单测可注入命中 |
| `NoOpPolicyDetector` | URL 空时工厂返回 |
| `HttpPolicyDetector` | POST JSON；缺 URL 不在 import 崩溃 |
| `get_policy_detector()` | 可 override |

协议实现不依赖 ORM。远程命中与本地命中合并后再决策。

### 6. 运行时衔接

- `ContextVar` 挂当前 Evaluator（类似 Collector）；prefork 后重置。
- `wrap_guardrail_node`：`kind` 为入口节点时先 `check_input`（拼接 `messages` + `variables.input`）；`kind=llm` 时对助手 `content` / `last_output` 做 `check_output`，mask 则写回 state。
- `execute_envelope`：加载规则、attach、`ainvoke` 后 `flush`（成功/失败/HITL 中断均 flush）；HITL 中断不当次做最终 output 全量拦截（节点内已处理的除外）。
- 包装顺序：先护栏再观测 span，或先 span 再护栏——本轮 **外层观测、内层护栏**，使 block 仍落在节点 span 内。

本轮不做：SSE 中间件截 token、限流、审计门面、FastAPI。

### 7. 依赖与测试

无新必选第三方（HTTP 用现有 `httpx`）。单测：规则优先级、mask/block、Fake 远程、关闭开关、llm 节点 mask、builtin 空库。集成：violation 写入 Postgres（`integration`）。

## 验收标准

1. ruff 无 error；新增/既有 pytest 通过。
2. `check_input` 命中 jailbreak → `block` + 可 flush 到 `sec_policy_violation`。
3. `check_output` 命中 pii/keyword → 按规则 mask 或 block；excerpt 不含明文 PII。
4. `guardrail_enabled=false` 时恒 allow、不写违规。
5. `guardrail_policy_url` 为空无外网调用；注入 Fake 可断言 detect 被调用。
6. 一次 llm 图 run 可在节点包装下 mask 输出；block 时 Run=`failed`。
7. 不新增 FastAPI 与 RateLimiter。
