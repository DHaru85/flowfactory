# 2026-08-19 服务层说明文档整理 - 服务层 - 修改

## 用户需求理解

在服务层基础设施（运行时、编排、鉴权、知识检索、工具分发、可观测、对象存储等）已落地、应用层尚未全面接入的前提下，**整理当前 `src/backend/service/` 下各服务**，并写入服务说明文档，覆盖：

1. **使用说明**：应用层 / 其它服务如何调用入口、关键类型、配置项、测试注入方式。
2. **原理**：职责边界、与映射层/数据层的关系、关键不变量（例如 Temporal 不写图内 checkpoint）。
3. **工作 / 协作流程**：单服务内部流水线，以及跨服务调用链（例如 Run → Celery → FlowRuntime → LLM/HITL → TraceCollector）。
4. **扩展功能指南**：如何按现有协议 + Fake + 工厂 override 模式接入新实现（新节点 kind、新 builtin 工具、新切片策略、新适配器等）。

本轮**只写文档**：不改 Python 业务代码、不新增 FastAPI 路由。表结构与 Schema 字段仍以 `docs/design/data_schema_server.md` 为准，本说明文档引用而不重复展开列级定义。

### 3. 各章必须写清的内容（对照现状）

**runtime**：`start/resume/cancel` 经 Orchestrator → Scheduler 入队；Worker 内 `execute_envelope` hydrate → `ainvoke`；节点 kind 现状为 `passthrough` / `interrupt` / `llm`；checkpoint 在 Postgres；HITL pending / Beat cron + Redis 锁。扩展：新增节点 kind 时改 `flow.py` 编译规则并同步观测包装。

**celery_app**：prefork 信号重建 DB/Redis、重置观测 ContextVar；队列 `wf.run` / `wf.beat` / `kb.ingest`；eager 默认。扩展：新长任务在 `tasks.py` 注册、用 `session_scope` + `run_coro_factory`，禁止占 FastAPI 事件循环。

**orchestration**：默认 `PassthroughOrchestrator`；`temporal_enabled` 切骨架。硬约束：Temporal Activity 只调服务层，不写 LangGraph checkpoint。

**auth**：本地 Argon2 → JWT + refresh 族；登出 jti 黑名单；`PermissionService` RBAC + 超管直通。LDAP 协议/Fake/`Ldap3Adapter` 预留。扩展：换目录适配器走工厂，不改 `AuthService` 登录顺序。

**knowledge**：parse → chunk 策略 → embed(bge-m3 1024) → tsvector → RRF；ONNX 重排路径可空。扩展：新切片策略注册到 `KNOWN_STRATEGIES`；embedding/rerank 走 override。

**storage**：`ObjectStore` 协议；MinIO public GET。扩展：新实现实现协议并改工厂。

**tools**：按 `agent_tool.kind` 分发 builtin/http/mcp；HTTP URL 仅来自配置；业务失败返回 `success=false`。扩展：`register_builtin`；MCP 走 `McpClientSession`。

**observability**：一次 envelope 一条 root trace，结束即 flush `obs_*`；prompt 脱敏 + hash；LangFuse 默认关闭。扩展：新节点包装、新 reporter 实现协议。

**支撑设施**：`session_scope` / 线程局部引擎；`get_repositories`；各 `*CacheStore` 与 key 约定。扩展：新仓储跟 ORM 域走，不在业务服务内散写 SQL。
