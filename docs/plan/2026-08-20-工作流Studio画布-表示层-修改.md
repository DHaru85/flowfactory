## 施工方案

1. 菜单：`studio` 且 `can_use` 时出现「Studio」；路由 `/studio` 列表、`/studio/:flowId` 画布。`can_control` 才显示创建/保存/发布/新草稿。
2. API：补全 flows CRUD、publish、new-draft、llms/tools 目录；类型对齐 `FlowDefinitionV1`。v0 图不进编辑器（服务端列表已跳过）。
3. 画布：引入 `@xyflow/react`。拖拽只写 `view.nodes`；连线写入 `edges`；条件路由写入 `branches`（画布上以带标签边展示）。节点类型覆盖 `start|end|llm|tool|assign|hitl|subgraph|custom`，右侧属性面板按类型编辑 `data`。
4. 权限：非 draft 或无完全控制为只读。发布前客户端做基本校验（唯一 id、恰一个 start、至少一个 end、必填 data）；最终以服务端 `definition_invalid` 为准。
5. 本轮不做：嵌套画布下钻、知识库、Docker 前端镜像、HITL 恢复 HTTP。
6. `npm run build` 通过。

## 验收标准

1. 可创建 draft、保存、发布、基于 published 开新草稿。
2. 图编辑器坐标只进 `view`，拓扑不写进 `view`。
3. 无 `can_control` 时只能看列表/详情，不能改草稿。
4. `npm run build` 成功。
