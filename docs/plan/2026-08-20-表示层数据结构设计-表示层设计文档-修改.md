# 2026-08-20 表示层数据结构设计 - 表示层设计文档 - 修改

## 用户需求理解

对照 [data_schema_server.md](../design/data_schema_server.md) 与 [api_reference_server.md](../design/api_reference_server.md)，编写表示层 React 工程的数据结构说明 **`docs/design/data_schema_client.md`**。文档供后续 Vite + React 工程落地 TypeScript 类型与会话/画布状态时作为契约，本轮**只写设计文档**，不创建 `src/frontend`、不改后端代码。

服务端三类形态（数据 / 可运行对象 / 序列化对象）面向 ORM、进程内服务与 Pydantic。浏览器没有表、没有 Celery/LDAP 客户端。客户端文档按同等粒度改写为三类，并与现网 HTTP JSON 对齐（以 `src/backend/api/apps/*/schemas.py` 与 SSE 协议为准，不以 ORM 列全集为准）。

### 澄清过程

本轮按下列默认约定推进。用户确认（2026-08-20）：**暂未开放 HTTP 的域保留空章**（三级标题与三类形态骨架保留，字段表标「待补」），不把整域从目录中抹掉。

## 需求中的待澄清事项

无待澄清事项。方案已锁定。

1. **范围**：已有公开 HTTP / SSE 的类型完整展开。知识库、领域图、护栏规则管理、审计计量、观测台、Webhook、HITL 待办 REST、组织/角色/配额/LDAP 管理等尚无应用层接口的域：**保留空章**，不抄服务端 ORM 列。
2. **形态分类**（对应服务端三类）：
   - **传输对象**：Axios / `fetch` / SSE `data` JSON，字段名与响应体一致。
   - **可运行对象**：浏览器内生命周期实例（鉴权会话、SSE 订阅、画布编辑会话），不落库。
   - **视图模型**：仅 UI 需要的派生态（流式消息缓冲、侧栏应用列表、画布选中集），禁止把 Redis key、password_hash、checkpointer 字节等服务端内部态写入前端。
3. **类型映射**：UUID → `string`；TIMESTAMPTZ / datetime → ISO 8601 `string`；JSONB 能收窄的写成联合类型，否则 `Record<string, unknown>`；密钥只出现在**请求**体，响应用 `has_api_key`。
4. **写法**：与服务端文档同构——按功能域二级标题，域内再分三类；字段用表格。TypeScript 名称用 PascalCase，并注明对应 Python `*Out` / `*Body`。
5. **列表**：现网多为裸数组 + `offset`/`limit` 查询参数，无 `{items,total}` 包装；文档如实记录，不发明分页信封。
6. **不在本轮**：实现 `.ts` 类型文件、OpenAPI 生成、Ant Design 表单 schema。

### 3. 各域必须写清的内容（对照现网）

**通用**

- `ErrorBody`：`{ code, message }`。
- Header：`Authorization: Bearer <access_token>`。
- 应用两档：`can_use` / `can_control`；超管语义只描述消费方式（前端以 `/auth/apps` 与 `/me` 为准，不解析 JWT 内全部 claims 作为授权源，避免与服务端 AccessControl 双真相）。

**健康检查 `GET /health`**

- `HealthOut`：`status`、`apps`、`services`。

**鉴权**

- 传输：`LoginBody`、`RefreshBody`、`LogoutBody`、`TokenPair`、`MeOut`、`AppVisibilityOut`、`BindingItem` / `BindingPutBody`。
- 可运行：`AuthSession`（access / refresh 存放约定：内存 + 可刷新；**不**在文档中规定必须 localStorage，只列可选持久化与 XSS 风险一句）。
- 不进入：`password_hash`、refresh 表、JWT 黑名单 Redis、LDAP 配置与 Adapter。

**会话与 SSE**

- 传输：列表 `ConversationOut`（无 metadata）、详情 `ConversationDetailOut`（含 metadata；planner 的 `profile_id` 仅在此）、`MessageOut`、`SendMessageBody` / `PlannerSendMessageBody` / `SendMessageOut`、创建体。
- `app_key` 字面量：`planner` / `workflow` / `conversation`（兼容路径）。
- `MessageContentBlock` 判别联合（text / reasoning / tool_call / artifact）。
- SSE：`SseFrame` + 各 `event` 载荷；客户端状态机镜像服务端 `idle → subscribed → run_active → completed|failed`；非法帧丢弃不断开。
- 可运行：`ConversationSseClient`（EventSource 或 fetch stream、Last-Event-ID 预留、keepalive 忽略）。
- 视图：`StreamingMessageView`（按 `message_id` 拼接 `speaking`/`reasoning`，工具块按 `tool_call_id` 更新）。

**Studio / Flow**

- 目录：`ProfileCatalogOut`、`LlmCatalogOut`（无 config）、`ToolCatalogOut`、`PublishedFlowCodeOut`、`FlowOut`。
- **完整抄写** `FlowDefinitionV1` 及节点 `data` 判别、边/分支、`FlowView`（服务端已标明仅表示层）。编译忽略 `view`；画布只改 `view` 不应改拓扑语义。
- 可运行：`FlowCanvasSession`（当前 `flow_id`、draft 脏标记、选中 node/edge）。
- 不进入：`schema_version=0` 松散 dict（Studio 列表已跳过非 v1）；checkpoint schema 表。

**models**

- `LlmOut`：`config` 已打码 + `has_api_key`；`LlmCreateBody` / `LlmPatchBody` 可带 `api_key`；PATCH 空字符串不覆盖。
- `provider`：`openai` | `azure` | `local`。

**agent_config**

- Profile / Skill / Tool / Mcp / Beat 的 In/Out；Tool JSON 字段名 **`schema`**（与 Python alias 一致）。
- Beat：`flow_id` 与 `profile_id` 恰一；PATCH 仅 `cron` / `input_payload`。
- 绑定：`resource_type` 含 `application`（走 auth 路由）与配置四类。
- 不进入：`sys_asset`、`owner_organization_id` 作 ACL。

**工作流执行**

- 仅会话侧可见：`run_id`、Run 状态枚举（若详情未下发则只在文档说明「前端不得假设会话行上有 run 外键」）。
- 不进入：Celery envelope、Thread snapshot、child pending、Redis `wf:run:active`。
