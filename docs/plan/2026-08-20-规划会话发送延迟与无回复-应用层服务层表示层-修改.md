# 2026-08-20 规划会话发送延迟与无回复 - 应用层服务层表示层 - 修改

## 用户需求理解

规划会话提交消息后要等很久才「发出」，且看不到模型回复。怀疑 RabbitMQ 总线。

现网日志（会话 `d15d8da0-…`）：SSE 已 200；`stream` 调用 LLM 后 **22s / 66s** 才出现 `start_run` 完成与 `POST .../messages 200`。期间无 AMQP 报错。

根因不是 broker 宕掉，而是 **eager 用法让总线与界面都看不到增量**：

1. **`celery_eager=true` 同步等待整张图**：`apply()` → `run_coro_factory` 在新线程新 loop 里跑 LLM，调用方（uvicorn 事件循环）`.result()` 堵死。POST 要等生成结束才返回，前端 `await sendPlannerMessage` 期间不落气泡、不清空输入。
2. **事件循环被堵，AMQP 消费者与 SSE 写不出去**：worker 即使用独立 loop publish 到 `ff.stream`，uvicorn 侧 consume / `StreamingResponse` 也跑不动。看起来像「总线没把回复送到前端」。
3. **请求级 Session 在 `start()` 之后才 commit**：助手消息尚未提交，worker 的 `_finalize_assistant_message` 按 id 查不到行，不写 `content_blocks`。POST 返回后列表拉取到的是空助手气泡。`reloadMessages` 还会 `setStreamText({})`，即使迟到的 `speaking` 也会被清掉。
4. **规划节点用 `complete_turn` 整段返回**，只在结束后 `_publish_speaking(全文)`，没有 token 增量（workflow 的 llm 节点才是边 `stream` 边发）。

因此：延迟来自 HTTP 等 eager；无回复来自未提交行 + 前端等 POST + 清 stream；RabbitMQ 拓扑本身不是这次故障点，但 **eager 堵 loop 会让总线失效**。

## 施工方案

1. **发消息路由**：写入 user/assistant 后 `await session.commit()`，再 `runtime.start()`。
2. **eager 调度**：有 running loop 时 `await execute_envelope`（测试 `celery_eager_join=true`）或 `asyncio.create_task`（默认 false，POST 立即返回）。禁止在 uvicorn loop 上 `.result()` 等新线程。生产仍可用独立 worker（`celery_eager=false`）。
3. **规划节点**：无 tool spec 时走 `chat_client.stream`，每枚 token `_publish_speaking`。
4. **前端**：先乐观插入 user/assistant 并清空输入；reload 时仅在助手已有正文时丢掉对应 `streamText`。
