# 2026-08-19 文本切片、向量化与知识检索基础设施建设 - 服务层 - 修改

## 用户需求理解

在 Knowledge 域 ORM / 仓储 / Redis key 已落地的前提下，建设**知识检索服务层**基础设施，覆盖三点：

1. **文本切片**：从原文解析出 `kb_section` + `kb_chunk`（chunk id 作为向量、全文、对象存储对齐键）。原文支持 UTF-8 文本 / Markdown / **PDF**。
2. **向量化与全文索引**：批量 embedding 写入 `kb_chunk.embedding`（pgvector）；同步写入 `content_tsv`（tsvector）。入库走 Celery，FastAPI 不跑长任务。
3. **知识检索**：向量 + 全文双路召回，应用层 RRF 融合；重排 ONNX 模型路径可配置，未配置时恒等透传。

对齐 `docs/design/data_schema_server.md` 中的 `IngestionPipeline`、`RetrievalService` 及序列化对象。本轮**只做服务层**，不做 FastAPI 路由、不做 SSE、不写 docker-compose。Postgres / Redis 沿用现有实例。

## 施工方案（已锁定）

### 1. 配置

`settings/config.py`：

- MinIO：`minio_endpoint=192.168.129.53:9400`、`minio_bucket=flowfactory`、`minio_secure=false`、`minio_public=true`；`minio_access_key` / `minio_secret_key` 可空（public 读走匿名 HTTP GET；写入仍优先凭证）
- Embedding：`embedding_base_url=http://192.168.129.53:9997/v1`、`embedding_model=bge-m3`、`embedding_dim=1024`、`embedding_api_key` 可空占位
- 切片：`kb_chunk_strategy` 默认 `recursive`；`kb_chunk_size=800`；`kb_chunk_overlap=120`
- 全文：`kb_fts_config=simple`
- 检索：`kb_retrieve_top_k=20`、`kb_rrf_k=60`、`kb_rerank_top_n=10`
- 重排：`kb_rerank_onnx_path`、`kb_rerank_tokenizer_path`、`kb_rerank_max_length=512`（路径皆可配，空则 Identity）
- Celery：`celery_queue_ingest=kb.ingest`

### 2. 序列化对象

`service/knowledge/schemas.py`：

- `SectionDraft`、`ChunkDraft`、`ChunkParseResult`
- `EmbeddingInput` / `EmbeddingOutput` / `ChunkRef`
- `SearchQuery` / `SearchHit` / `SearchHitList` / `RerankResult`
- `IngestionJobStats`、`IngestDocumentRequest`
- `ChunkerOptions`：`strategy` / `chunk_size` / `chunk_overlap`（均可覆盖全局默认）

`SearchQuery.filters` 为 `dict[str, object] | None`。

### 3. 对象存储

`service/storage/`：`ObjectStore` 协议（`put` / `get` / `stat`）、`MemoryObjectStore`、`MinioObjectStore`（public GET 无凭证可读）、工厂可 override。

### 4. 解析与切片

- PDF：`pypdf` 按页抽文本；页作为 Section 元数据（`page`）。
- 文本/Markdown：UTF-8（失败 replace）。
- 策略注册表（名称可配，请求级可覆盖）：

| 名称 | 行为 |
| --- | --- |
| `recursive` | 默认。Markdown 标题或 PDF 页为 Section，Section 内按段落/句子递归切分 |
| `markdown` | 以标题块为主，超长再递归切 |
| `fixed` | 固定字符窗口 + overlap，整篇一个 Section |
| `page` | 按 PDF 页（或 `\f`）一块一 Section，页内过长再递归 |

未知策略名视为错误，job 失败。

### 5. Embedding 与全文

- OpenAI 兼容 `embeddings.create`，模型 `bge-m3`，维度 1024。
- 单测 / 默认真入测试用 `FakeEmbeddingClient`；集成可选真实服务。
- `to_tsvector(:config, :text)` 写 `content_tsv`。

### 6. 入库流水线

`IngestionPipeline`：锁 → fetch → 按 MIME/魔数 parse → 按策略切分 → 替换旧 section/chunk → embed → fulltext → 状态与 Redis 进度。

Celery：`ingest_knowledge_doc`，队列 `kb.ingest`。

### 7. 检索

双路召回 + RRF；`filters.doc_id` 与 JSONB `@>`。`rerank()` 使用可配置 ONNX。

### 8. 重排

- `kb_rerank_onnx_path` 空：`IdentityReranker`
- 路径非空：加载 `onnxruntime`；`kb_rerank_tokenizer_path` 用于 pair 编码；失败回退 Identity 并打错误日志
- 测试可用注入的 Fake Reranker

### 9. 映射层补丁

`DEFAULT_EMBEDDING_DIM=1024`；Alembic 将 `kb_chunk.embedding` 改为 `vector(1024)`。

### 10. 测试与施工状态

见验收标准。开工模块标 `施工中`，通过后改回 `空闲`。

## 验收标准

1. ruff 无 error；新增/既有 pytest 通过。
2. Markdown 与 **PDF 字节**均可入库切分；策略名可切换（recursive / markdown / fixed / page）。
3. Fake embed 下 job=`success`，chunk 含 1024 维向量与 `content_tsv`。
4. `search` + `fuse` 可召回；无 ONNX 时 Identity 重排可用。
5. 同一 `doc_id` Redis 锁阻止并发双写。
6. 默认 MinIO / embedding 配置与用户给定地址一致；不新增 FastAPI 与 docker-compose。
