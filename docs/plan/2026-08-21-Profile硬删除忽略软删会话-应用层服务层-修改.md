# 2026-08-21 Profile 硬删除忽略软删会话 - 应用层服务层 - 修改

## 用户需求理解

硬删 Profile 时，若其规划会话引用仅来自已软删（`status=deleted`）的会话，不应再 409，允许物理删除。未删除会话仍视为有效引用。

现状：`DELETE /agent-config/profiles/{id}` 只检查 `agent_flow` 全量行与 Beat；规划会话的 `profile_id` 在 `metadata`，无 FK，未参与引用判断。`count_flows_for_profile` 也不排除已软删 Flow，软删工作流仍会拦住 Profile。

## 需求中的待澄清事项

无待澄清事项（按与会话软删同一原则处理：未删除才算引用；已软删 Flow 同样不拦住 Profile。）

## 施工方案

1. `ConversationRepository.count_active_by_profile(profile_id)`：`status != deleted` 且 `metadata->>'profile_id'` 等于该 UUID。
2. `delete_profile`：上述计数 > 0 则 `409 profile_in_use`（文案：仍被未删除会话引用）。软删会话不计入，硬删后其 metadata 中的 id 可残留，不回写。
3. `count_flows_for_profile` 增加 `AgentFlow.status != "deleted"`，与 Flow 软删对齐。Beat 仍全量拦截。
4. 单测：规划会话软删后删 Profile 返回 200；未删会话则 409。相关 pytest、ruff。

## 方案待澄清事项

无待澄清事项
