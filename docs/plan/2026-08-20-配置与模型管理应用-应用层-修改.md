# 2026-08-20 配置与模型管理应用 - 应用层 - 修改

总纲：`2026-08-20-自主规划智能体与模型管理-应用层服务层-修改.md`（第 1 轮）。

## 用户需求理解

在自主规划智能体大型工程中，**本轮只建设配置与模型**，不建设规划主循环、不拆会话路径。

对齐已确认澄清：

- 模型抽成公共应用 `models`，服务 Studio 与未来规划循环；LLM 全局；密钥不回传；Studio `GET /llms` 只读兼容。
- Profile / Skill / Tool / MCP 配置管理走独立应用 `agent_config`。
- Profile **不按** `owner_organization_id` 隔离；与组织 / 部门 / 角色 / 个人的关系是 **绑定**。本轮 **不调用** `PermissionService.check`，但必须落下绑定数据与 `sys_asset` 登记，给以后 RBAC 审核留路径。
- Beat **只** 管理「绑工作流」的定时任务；规划智能体定时 **本轮不做、不改** `flow_id` 为空或加 `profile_id`。
- 不做前端、限流、真实 MCP 接通、Temporal、会话 `planner`/`workflow` 路径、SkillRuntime。

### 澄清过程

见总纲「澄清过程」Q1–Q8。本轮对应 Q4、Q5（工作流 Beat）、Q7（留 RBAC 路径）、Q8（先配置+模型）。Q2 不影响本轮。

## 需求中的待澄清事项

无待澄清事项（本轮范围）。若对「绑定表形态」或「创建接口是否本轮就只允许超管」有异议，见方案第 3 节默认：**本轮 JWT 均可写配置，绑定可读写但不按绑定过滤列表**；超管/RBAC 管理员创建权留到以后接 `PermissionService`。

### 1. 应用

| `app_key` | 前缀 | 职责 |
| --- | --- | --- |
| `models` | `/api/v1/models` | LLM 目录 CRUD、密钥打码、运行时解析客户端（供后续循环与现网 llm 节点共用） |

### 2. 应用 `models`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/llms` | 可含未激活；查询 `is_active` 可选。响应无明文 `api_key` |
| POST | `/llms` | `code` / `provider` / `model_name` / `config` |
| GET | `/llms/{id}` | `config.api_key` 打码（有则返回 `********` 或 `has_api_key=true`） |
| PATCH | `/llms/{id}` | `api_key` 空或省略表示不改 |
| POST | `/llms/{id}/deactivate` | `is_active=false` |

`provider`：`openai` / `azure` / `local`。`code` 冲突 409。无 token 401。

`service/runtime` 增加 `resolve_llm_client(llm_id | code)`：从 `agent_llm.config` 读 `base_url` / `api_key` / `model_name`，缺省回退环境变量 `llm_*`。Studio 图执行路径可在本轮改为走解析（若改动面过大则仅提供函数，llm 节点下一轮再接；**默认本轮 llm 节点改用解析**，便于 Studio 与 models 真正共用）。

Studio `GET /api/v1/studio/llms` 保留，仍只读活跃项、不下发 `config`。

### 3. RBAC 路径（本轮落数据，不审核）

现网 `PermissionService` 只认 **角色 → `sys_asset`**，没有组织/部门/个人直接授权。用户要的是 Profile（及以后 Skill/MCP）绑定到 **organization / department / role / user**。

本轮新增表 `agent_resource_binding`（映射层 Agent，Alembic）：

| 列 | 说明 |
| --- | --- |
| `id` | UUID PK |
| `resource_type` | `profile` / `skill` / `tool` / `mcp_server` |
| `resource_id` | 对应表 UUID |
| `subject_type` | `organization` / `department` / `role` / `user` |
| `subject_id` | 主体 UUID |
| `actions` | JSONB，默认 `["read","use"]`；管理员绑定以后用 `admin` |
| 时间戳 | created_at / updated_at |

唯一：`(resource_type, resource_id, subject_type, subject_id)`。

创建 Profile / Skill / Tool / MCP 时 **同时** 写入 `sys_asset`：

- `asset_type`：同上四类字符串（写入设计文档枚举）
- `asset_key`：资源 UUID 的 canonical 字符串（稳定，改 `code` 不影响授权键）
- `name`：展示名

**本轮不调用** `PermissionService.check` / `list_accessible_assets`。列表对任意 JWT 全量可见（与 Studio 阶段相同）。绑定的 GET/PUT 接口可用，便于以后把过滤改成：超管全看；管理员看权限范围内绑定；普通人看命中自己 org/dept/roles/id 的绑定。

不把 `agent_profile.owner_organization_id` 当 ACL；列保留不在本轮删除、本轮接口不依赖它。

以后接 RBAC 时的预留点（本轮只写进 `api_reference` / `data_schema`，不实现）：

- 创建/改绑定：要求对 `asset_type=application` `asset_key=agent_config` 的 `admin`，或 `user.is_superuser`。
- 可见性：先读 `agent_resource_binding`，再与 `PermissionService` 角色 grant 求并集（个人/部门/组织绑定是现网 grant 表的扩展，**以后**可升到 Permission 域，本轮放 Agent 表以免大改鉴权包）。

### 4. 应用 `agent_config`

前缀 `/api/v1/agent-config`。需 JWT。非法 FK 400，code 冲突 409，不存在 404。

**Profile**

- `GET/POST /profiles`，`GET/PATCH /profiles/{id}`
- `GET/PUT /profiles/{id}/bindings`：覆盖式写入绑定列表
- 字段：`code` / `name` / `system_prompt` / `default_llm_id` / `skill_ids`；校验 LLM、Skill 存在

**Skill**

- CRUD + `/skills/{id}/bindings`
- `tool_ids` / `prompt_template`；仓储补 `AgentSkill`

**Tool**

- CRUD + `/tools/{id}/bindings`（路径预留，与 Q7 一致）
- `kind=mcp` 必须 `mcp_server_id`

**MCP**

- CRUD + `/mcp-servers/{id}/bindings`
- 不探测真实连通；`transport`：`stdio` / `sse`

**Beat（仅工作流）**

- `GET/POST /beat-tasks`，`GET/PATCH /beat-tasks/{id}`，`POST /beat-tasks/{id}/enable` 与 `/disable`
- 创建必须带已存在的 `flow_id`；`cron` 用 `croniter` 校验
- **禁止** `profile_id` 字段；不改 `agent_beat_task` 表结构；不改 `dispatch_due_tasks` 语义
- 规划侧定时：总纲「以后」轮次，本轮文档写明暂缓
