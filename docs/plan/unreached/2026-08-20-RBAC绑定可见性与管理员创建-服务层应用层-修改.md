## 用户需求理解

Profile（及 Skill / MCP 等）不按 `owner_organization_id` 隔离，而按绑定到组织 / 部门 / 角色 / 个人决定可见性。仅 RBAC 管理员或系统总管理员可创建 Profile 并写绑定。管理员看见权限范围内全部 Profile；普通人只见命中自身主体的资源。

## 施工方案

1. 创建/改绑定：`user.is_superuser` 或对 `asset_type=application` `asset_key=agent_config` 具 `admin`。否则 403。
2. 列表/详情：超管全量；管理员按其组织/部门范围并集绑定；普通用户匹配 `subject_type/user|role|department|organization` 与自身 `id` / 角色 / `department_id` / `organization_id`（含上级组织是否计入：开工时默认**仅直接组织**，不自动继承父组织，除非设计文档另述）。
3. **不调用过滤则视为越权**；404 代替 403 探测（跨范围详情）。
4. 现网 `PermissionService` 仅角色→资产；本轮以 binding 表为主，角色 grant 为并集。不把 binding 升到 Permission 域，除非本轮明确要搬。
5. 不删 `owner_organization_id`。
6. 单测：普通人看不到未绑定 Profile；超管可建；无 admin 创建 403。
