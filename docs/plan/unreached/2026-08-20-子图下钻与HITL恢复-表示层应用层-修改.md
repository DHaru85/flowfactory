## 施工方案

### A. 子图画布下钻（表示层，可复用现网 `GET /studio/flows`）

1. 属性面板在已选 `flow_code` 后提供「下钻」。按 `code` + `status=published` 拉列表，匹配 `version`（空则取该 code 最大已发布版本），再 `GET /studio/flows/{id}` 取完整 `definition`。
2. 会话栈：`{ flowId, document, readOnly: true }[]`。下钻 push，面包屑 pop。父草稿的 `dirty` / 拓扑编辑器在栈深 > 0 时禁用。
3. 只读画布仍渲染 `view` 坐标与 nodes/edges/branches；不可保存父图以外的 definition。
4. 目标不存在、非 v1、`403`：提示，不 push。code 级环：栈内已出现同一 `flow_code@version` 则拒绝再下钻。
5. 不在父 `definition.nodes` 里内嵌子节点。不改 compile。

若现网按 `code` 过滤不够用（多版本），应用层可加只读 `GET /studio/flows/by-code/{code}?version=`；能用列表查询则不加接口。

### B. HITL 恢复（应用层 + 表示层）

服务层保持：`create_pending` → Run `interrupted`；`resume(HitlResumeInput)` → `Command(resume=...)` 入队。`on_reject=fail` 拒绝即取消 Run；`route` 写入 `variables.hitl_resume` 供 `hitl_decision` 分支。

1. 补齐客户端传输对象（写入 `data_schema_client.md` Workflow 章，不再留空）：`HitlPendingOut`、`HitlResumeBody`（对齐 `hitl_id` / `decision` / `user_input`）。`form_schema` 随 pending 或从节点定义带出，供表单渲染。
2. HTTP（建议挂 `conversation`，JWT + 属主校验；越权 `404`）：
   - `GET /api/v1/conversations/workflow/hitl-pendings`（仅 `pending`，可按 `run_id` 过滤）
   - `GET /api/v1/conversations/workflow/hitl-pendings/{hitl_id}`
   - `POST /api/v1/conversations/workflow/hitl-pendings/{hitl_id}/resume` → 调 `WorkflowRuntimeService.resume`
3. 错误：不存在/非 pending `400 hitl_not_resumable`；过期走现网 `expire_hitl_pending`（`expired` + Run `cancelled`），前端展示不可恢复。
4. 表示层：工作流会话在 SSE `run` 中断后拉 pending；按 `form_schema` 渲染（无 schema 则文本 + 批准/拒绝）；提交后继续订 SSE。规划会话不接 HITL。
5. SSE 若现网无 `interrupted` 帧，本轮可在 worker 写 pending 后补一条事件，或前端对 `run_id` 轮询 pending。优先补事件，避免空转轮询。

### 明确不做

知识库、Docker 前端镜像、嵌套 compile、子图 waiting 管理台、Run 列表/取消全套、Temporal `signal_hitl` 替换 Passthrough。
