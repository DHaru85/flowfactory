# 2026-08-20 本地用户自助注册 - 服务层应用层表示层 - 修改

## 用户需求理解

登录页没有注册入口。现网只有 `POST /auth/login`，无用户自助创建能力。本轮补注册 API 与表示层入口。

### 澄清过程

用户指出界面缺注册。本轮按默认约定（未另开澄清轮次）：

- 开放 `POST /api/v1/auth/register`（无需 Token）。
- 保证存在 `sys_organization.code=default`。
- **库中尚无未删除用户**时，该账号 `is_superuser=true`（便于首启）。
- 之后注册的用户加入同一默认组织，非超管（应用可见性仍靠绑定）。
- 成功后签发与登录相同的 `TokenPair`。
- 不开放选组织、不写 email（可空）、不做验证码。

## 需求中的待澄清事项

无待澄清事项。

## 施工方案

1. `AuthService.register`：校验用户名唯一；幂等创建 default 组织；首用户超管；Argon2 写 `password_hash`；再 `_issue_pair`。
2. `POST /api/v1/auth/register`：`username` / `password`（≥8）/ 可选 `display_name`（默认等于用户名）。冲突 `409 username_conflict`。
3. 前端 `/register` 页；登录页增加链接。Axios 401 刷新跳过 `/auth/register`。
4. 更新 `api_reference_server.md` 与 `data_schema_client.md` 注册传输对象。
5. pytest + `npm run build`。

## 方案待澄清事项

无待澄清事项（方案锁定）。

## 验收标准

1. 无用户时注册得到超管并可登录进应用。
2. 同名 `409 username_conflict`。
3. 登录页可进入注册页。
4. 相关 pytest 通过；前端 `npm run build` 通过。
